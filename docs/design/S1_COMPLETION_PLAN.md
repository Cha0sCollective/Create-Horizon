# Adopted S1 completion plan

Owner adopted this plan on November 3, 2026, explicitly deferred paired Open to
LAN, authorized deliverable 1, and required consultation before further scope
expansion. Independent read-only Sol High scope review accepted this plan with
the corrections below incorporated. G1 remains OPEN. No release authority.

## Supported outcome

One registered generic counter, one owned inventory slot, one current schema,
one retained diagnostic visual: default integrated singleplayer, dedicated server
with two real matching clients, and the adopted in-frame comparison. Begin with
fresh bounded Overworld simulation. Preserve dimension/session identity,
transition invalidation and correct snapshots on re-entry; unsupported simulation
targets refuse safely. One dimension-scoped transaction does not waive transitions.

The server executes actual Wasm callbacks and owns committed state. Placement,
replacement/removal, activity/unload/reload, authorized player transfer, save/reopen,
coherent interrupted recovery, exact admission, reconnect/resync and server-timed
animation are required. Trap/fuel/invalid output abort without partial effects;
reset guest caches from committed state. Verify actual supported item/network
roundtrips without fallback IDs or silently lost components.

## Reuse and deferral

Reuse Horizon Game, simulation, memory/TCP, native owners/codecs, streaming,
resources, renderer and Wasm runtime; reuse our accepted paired content, counter,
slot, retirement, checkpoint, transport and client work. Independent native saves
do not establish cross-owner consistency. Login negotiation is already composed
but agreement still stops before paired configuration/admission. Accepted H11
visual work is on another branch: integrate and validate, do not reimplement it.

Defer arbitrary existing worlds/imports, unrestricted generators/subsystems,
general addon/machine/menu/inventory frameworks, migrations, broad journal or
region-format redesign, extra fault combinations unreachable from this profile,
release packaging/assets and full hardware/performance certification. Record
bounded costs. Kinetics/milling and later gameplay remain outside S1.

Paired Open to LAN publishing is deferred by explicit owner decision. Keep its
current refusal and negative regression. This revises that topology in the later
C1 proposal; do not claim the old full C1 topology completed. Default integrated
memory play, dedicated two-client TCP and in-frame acceptance remain required.

## Four deliverables

1. Connected usable paired world: fix fresh-player admission; map actual startup,
   save and close callers; choose the smallest safe reusable route; connect actual
   integrated Memory frontend and in-frame ownership to existing client/server
   components; complete C0 closure and exact C1 configuration/admission for the
   supported modes. Prove fresh/rejoin/close/error behavior. Keep filled machine
   ingress closed until checkpoint and departure custody are connected.
2. Persistent playable machine: ordinary placement/lifecycle/generations, actual
   persistent Wasm bridge, authorized one-slot transfer with stale/replay/reach/
   permission checks, removal/disposal, callback rollback and coherent save/reopen
   covering every reachable item owner. Interrupted publication selects a complete
   checkpoint without duplication/loss.
3. Synchronized animated machine: initial/delta state, revisions/gap/full resync,
   reconnect/untrack, integrate existing retained visual, tick-anchored stop/reverse/
   pause and cleanup. Two clients agree; dedicated allocates no renderer.
4. Combined G1 acceptance: shared ordinary scenario in default integrated,
   dedicated/two real clients and in-frame; focused callback/replay/stale/mismatch/
   save-fault controls; explicit outcome checklist and G1 decision.

Deliverables can require several small patches. Handshake/presentation may overlap
once interfaces stabilize. No standing team or concurrent source/compiler/Git writes.

## Scope and validation control

Before adding a prerequisite, identify the missing S1 behavior, actual failing
caller and smallest repair. Ask the owner BEFORE expanding the supported profile,
introducing a broad engine redesign or revising acceptance. Difficulty alone does
not authorize expansion. Existing working code need not be discarded.

Use appropriate compile/lint checks, focused behavior tests and affected
regressions; reuse unchanged evidence with attribution. Run combined game checks
at integration milestones. Do not multiply historical full batteries for wrappers
or mechanical edits. Preserve upstream affected checks, independent substantive/
source review and different final/privacy requirements. Frozen evidence/failures
remain immutable; a correction after frozen FINAL uses a new prefix.
