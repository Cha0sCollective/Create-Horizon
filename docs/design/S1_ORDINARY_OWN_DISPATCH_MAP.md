server worker, but must not block the in-frame frontend. Game contains a plain

can activate only the captured empty counter. It already validates captured BlockItem/

## Decisions before source release

Close before complete admission must remain honest. Current recovery expects one
integrated owner or two external players; do not invent a zero/partial-roster promise.
Classify actual pre-editability cancellation through retained closure, preserve
native files and retain accepted zero-complete-epoch refusal. Published editable
ownership cannot be relabeled unacquired cancellation. If solving this needs new
roster semantics/schema/initial autosave or revised acceptance, ask the owner first.

Departure, filled slot transfer and fault disposal remain separate. Freezing the
original close roster plus an empty counter does not establish spontaneous departure
custody. Replication/H11 and combined G1 also remain following work.

The coordinator may split this maximum budget into smaller packets: server OWN/
Unplaced dispatch, responsive LOCAL frontend recovery, then empty counter admission.
A split must keep every existing enabled route working and explicitly leave the new
route refused until its own adapter is ready. Do not activate half a frontend or
silently broaden a supported profile merely to shrink a patch.
