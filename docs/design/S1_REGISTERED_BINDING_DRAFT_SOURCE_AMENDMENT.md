## Concrete risks and unchanged refusal boundaries

1. Profile ambiguity while Dormant still requires the already proposed exact
   counter kinds native-counter-checkpoint/native-registered-counter-checkpoint
   at format2 and slot kinds native-slot-checkpoint/native-registered-slot-
   checkpoint at format1. Envelope format1 remains unchanged. This retains the
   main proposal's honest format-profile extension, unknown/mixed-profile refusal
   and no migration/backward-compatibility promise. It adds no new kind or field.
2. Active-key-only recovery is an actual implementation obstacle, not permission
   to change legacy RecoveryReceipt/NativeRecoveryParts signatures or their
   unscoped callers. Registered paired Active/Dormant receipts and private
   concrete sharing must fit session_checkpoint.rs. No fake keys, cleared domain,
   lost retirement or weakened final player/item verification may evade it.
3. D's real item column union, arrival comparison before staging, checked native
   installer and final fence must remain in the registered recovery route.
   Refactoring may not open before strict palette/profile correlation, omit a
   delivered ItemEntity or substitute fabricated verified origins/providers.
4. Materialized resources are not supplied by the existing vanilla OnceLock.
   Build the actual owned-resource fixture inside the two already scoped test
   files, using real captured content and actual Assets/RenderAssets loaders.
   Require intended Loaded.root, no fallback, exact alias/default/reverse mapping,
   collision/model evidence and unchanged shared inputs. Reuse existing loaders
   without mod_content.rs/game.rs/peer_contract_snapshot_tests.rs production edits.
5. Existing native tests may use small closed registries for pure validation;
   actual registered positive controls cannot. Resource absence, fallback,
   borrowed vanilla IDs or skipped positive cases are failures, not an expanded
   test allowance. No test may launch a compiler, Java or another test process.
6. Adding profile fields touches literals. Enumerate full NativeBinding/Header/
   frame/view/receipt callers first; keep all required edits within the exact
   seven paths. An unavoidable eighth path blocks that part pending explicit
   revised design and fresh review. No new dependency or sidecar format is
   authorized to make the draft easier.

The only rationale for earlier drafting is that these interfaces are already
visible in exact composed source and the parent's isolated broad does not need
the child files. Native-file drafting can overlap that waiting period without
changing its evidence. It cannot establish compile correctness, completed
materialization, child runtime success or parent acceptance.

No lifecycle/ordinary placement, Running, startup/close, player authorization,
network admission, default activation, G1, public push/PR/merge/release or later
stage authority is added. The registered main proposal and all existing
operating/review/preservation boundaries remain in force.
